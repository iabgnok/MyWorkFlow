# MyWorkflow 分阶段实现计划

> 基于“先做减法、小步快跑”的最小可验证模型（MVP）演进策略

本计划旨在将庞大且复杂的 MyWorkflow 架构拆解为可落地的四个阶段。核心思想是**“先让系统在纯内存与 CLI 下跑通一条简单的直线，再逐步堆叠持久化、安全机制与元编程架构”**。

---

## 阶段一：核心骨架搭建与 MVP 验证 (V0.1)

**目标**：不依赖数据库、不依赖复杂 AST 解析，仅靠内存状态机跑通人工编写的第一个 `.step.md` 剧本。

**核心任务**：

1. **轻量级解析器 (`parser.py`)**：
   - 放弃 `mistune` (AST)，直接使用正则（`re.split(r'(?m)^## Step\s+\d+')`）切割 Markdown。
   - 解析 YAML frontmatter 和提取输入/输出变量声明。
   - 实现**深度类型安全的变量替换**（避免 `{{var}}` 将嵌套 JSON 强制破坏的 bug）。
2. **纯内存调度器 (`runner.py`)**：
   - 实现基于内存字典的 `RunState`，暂不接入 SQLite。
   - 按序执行 Steps，实现简单的变量传递（Step 1 的 Output 能作为 Step 2 的 Input）。
   - 暂不处理 [SUB_WORKFLOW] 的递归调用。
3. **实现两大基础技能 (`skills/atomic/`)**：
   - `llm_prompt_call.py`：接入 LLM API，支持最基础的字符串与 JSON 格式化输出。
   - `file_writer.py` 或 `shell_executor.py`：实现一个具备副作用的基础技能用于验证闭环。
   - *注：安全保险箱 `secrets_vault` 暂缓，直接从 `.env` 读取明文 API Key。*

**里程碑 (Milestone 1)**：

- 手写一个 `hello_world.step.md`（例如：读取一个文本 -> 让 LLM 总结 -> 写入新文件）。
- 通过 CLI 执行 `python runner.py --file hello_world.step.md` 能够成功从头跑到尾，输出预期文件。

---

## 阶段二：状态持久化与错误恢复 (V0.2)

**目标**：引入“断点续传”能力，解决 LLM 调用时常发生的超时、掉线或 JSON 解析失败问题。

**核心任务**：

1. **SQLite 状态机 (`state_store.py`)**：
   - 按照文档设计建立 `step_states` 和 `run_meta` 表。
   - 每执行完一个 Step 立即进行 `db.commit()`。
   - `runner.py` 改造为在启动时读取数据库，跳过状态为 `done` 的步骤。
   - **构建 Handoff Artifact (交接快照) 基础**：确保 `run_meta.var_snapshot` 能随时导出完整且结构合法的 JSON，为后期的 Context Reset 铺路。
   - **脱敏落盘（关键安全优化）**：在序列化 input_json 和 output_json 前，把 `required_secrets` 中声明的敏感字段替换为 `"***"`，保证 API Key 绝光明文不落盘。
2. **基础错误路由 (`error_policy.py`)**：
   - 实现 `FailureAction.RETRY` 和 `FailureAction.SKIP`。
   - 引入 `tenacity` 库实现 L0/L1 技能的自动重试。
   - 对于 L2 错误，暂不实现复杂的 Rollback（代码备份还原等），直接将工作流标记为 `failed` 并终止。
3. **CLI 交互闸门 (`user_confirm.py`)**：
   - 识别 `[CONFIRM]` 标签。
   - 暂缓 VS Code IPC 通信，先实现终端底层的 `stdin` 阻塞等待（Y/N 继续）。

**里程碑 (Milestone 2)**：

- 在工作流运行到一半时，强行 `Ctrl+C` 杀掉进程。
- 再次执行相同 `run_id` 的命令，系统能准确从中断的步骤恢复并继续执行，且前面步骤的变量未丢失。

## 阶段三：工作流嵌套与 META_CREATOR 三角色闭环 (V0.5)

**目标**：打通动态生成和调用子工作流的能力，让引擎从线性瀑布流升级为支持反馈闭环（Feedback Loop）的智能体状态机。

**核心任务**：

1. **状态机支持重入与变量映射**：
   - 为子工作流引入 `output_mapping` 机制，解决递归时全局命名空间污染的问题。
   - 强化 `runner.py`，支持带错漏坐标的 **Jump Back (向后跳转)** 逻辑。允许流转指针在被判定失败后重新返回到指定步骤。
2. **重构核心 META 工作流 (三角色迭代模式)**：
   （通过prompt来规定角色人格）
   - 角色 1 Planner (`workflow_planner.step.md`)：输出蓝图 `Workflow_Blueprint.json`，并根据**逻辑块独立性**判断是否需要子工作流拆解（>7步强制拆解）。
   - 角色 2 Generator (`workflow_designer.step.md`)：基于“全量交付 (Full Artifact Delivery)”策略一气呵成生成草稿。若被由于退回指令触发，则使用 Editing（精准编辑）能力局部重写代码。
   - 角色 3 Evaluator (`quality_evaluator.step.md`)：代替原来的粗暴扫描，进行整篇扫描后输出具备四维评分及“点对点错漏坐标”的 JSON 反馈报告。
3. **注册表管理 (`registry_manager.py`)**：
   - 完善工作流审核通过后的持久化与注册逻辑（带并发防护与版本自增）。

**里程碑 (Milestone 3)**：

- 向系统下发指令：“帮我创建一个代码 Review 工作流”。
- 能亲眼在日志中观察到：Planner 设计 -> Generator 写完全体 -> Evaluator 打回某个未定义的变量并给出坐标 -> Generator 精准 Editing 修改 -> 再次通过后最终成功注册进 `index.json`。

## 阶段四：安全加固、Context Reset 与极高阶工程化 (V1.0 - V2.0 终态)

**目标**：彻底解决 LLM 长期调用的幻觉问题，并补齐所有工业级高阶特性和安全执行沙盒。

**核心任务**：

1. **Context Reset (硬重置) 机制 (`context_manager.py` 重写版)**：
   - 彻底废弃 LLM 依赖语义摘要压缩历史记录的设计。
   - 在发生 Jump Back 打回（生成-评审重新迭代）或长任务调用时，清空当前 LLM 对话记录（Message History），用上一步状态机里生成的 `Handoff Artifact (JSON快照)` 作为 System Prompt 重启，为下一步操作提供“干净的石板”。
2. **阶梯式重试策略 (Escalation Ladder)**：
   - 引入 4 轮死循环防控机制：标准重试 -> CoT 强化要求 -> 评分标准下调 (Relaxation) -> 强行触发底层 `[CONFIRM]` 强制人工干预（Human-in-the-loop）。
3. **自动化安全求值与审计沙盒**：
   - 将现有不安全的 `eval()` 跳过判断，完全替换为受限无副执行的沙盒解析引擎 `simpleeval`。
   - Evaluator 安全门禁加入静态正则词扫描优先原则（绝对禁止 LLM 将风险自定降级）。
4. **自动化测试与高阶数据防护**：
   - 引入 `unit_test_generator`，确保最终生成的子流程都能一次跑通。
   - 重构 `user_confirm` 机制，不仅拦截危险侧面影响 (Side Effects)，还准备接入 VS Code 的 UI Extension 协议实现 IDE 无缝弹窗审批。
   - Secrets Vault 升级真实的内存层混淆加扰（而不只是单纯过滤日志）。

**里程碑 (Milestone 4)**：

- 向系统下发一句需求即可闭环获得：设计审查 -> 源码生成 -> 依赖测试 -> 静态扫描 -> 沙箱试运行 -> 报告输出 的全自动工业级体验。
