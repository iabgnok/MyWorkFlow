# MyWorkflow 分阶段实现计划

> 基于“先做减法、小步快跑”的最小可验证模型（MVP）演进策略

本计划旨在将庞大且复杂的 MyWorkflow 架构拆解为可落地的四个阶段。核心思想是**“先让系统在纯内存与 CLI 下跑通一条简单的直线，再逐步堆叠持久化、安全机制与元编程架构”**。

---

## 阶段一：核心骨架搭建与 MVP 验证 (V0.1)

**目标**：不依赖数据库、不依赖复杂 AST 解析，仅靠内存状态机跑通人工编写的第一个 `.step.md` 剧本。

**核心任务**：
1. **轻量级解析器 (`parser.py`)**：
   - 放弃 `mistune` (AST)，直接使用正则（`re.split(r'(?m)^## Step\s+\d+')`）切割 Markdown。
   - 解析 YAML frontmatter 和提取输入/输出变量声明。
   - 实现简单的全局扁平化变量字符串替换引擎（`{{var}}` 替换）。
2. **纯内存调度器 (`runner.py`)**：
   - 实现基于内存字典的 `RunState`，暂不接入 SQLite。
   - 按序执行 Steps，实现简单的变量传递（Step 1 的 Output 能作为 Step 2 的 Input）。
   - 暂不处理 [SUB_WORKFLOW] 的递归调用。
3. **实现两大基础技能 (`skills/atomic/`)**：
   - `llm_prompt_call.py`：接入 LLM API，支持最基础的字符串与 JSON 格式化输出。
   - `file_writer.py` 或 `shell_executor.py`：实现一个具备副作用的基础技能用于验证闭环。
   - *注：安全保险箱 `secrets_vault` 暂缓，直接从 `.env` 读取明文 API Key。*

**里程碑 (Milestone 1)**：
- 手写一个 `hello_world.step.md`（例如：读取一个文本 -> 让 LLM 总结 -> 写入新文件）。
- 通过 CLI 执行 `python runner.py --file hello_world.step.md` 能够成功从头跑到尾，输出预期文件。

---

## 阶段二：状态持久化与错误恢复 (V0.2)

**目标**：引入“断点续传”能力，解决 LLM 调用时常发生的超时、掉线或 JSON 解析失败问题。

**核心任务**：
1. **SQLite 状态机 (`state_store.py`)**：
   - 按照文档设计建立 `step_states` 和 `run_meta` 表。
   - 每执行完一个 Step 立即进行 `db.commit()`。
   - `runner.py` 改造为在启动时读取数据库，跳过状态为 `done` 的步骤。
2. **基础错误路由 (`error_policy.py`)**：
   - 实现 `FailureAction.RETRY` 和 `FailureAction.SKIP`。
   - 引入 `tenacity` 库实现 L0/L1 技能的自动重试。
   - 对于 L2 错误，暂不实现复杂的 Rollback（代码备份还原等），直接将工作流标记为 `failed` 并终止。
3. **CLI 交互闸门 (`user_confirm.py`)**：
   - 识别 `[CONFIRM]` 标签。
   - 暂缓 VS Code IPC 通信，先实现终端底层的 `stdin` 阻塞等待（Y/N 继续）。

**里程碑 (Milestone 2)**：
- 在工作流运行到一半时，强行 `Ctrl+C` 杀掉进程。
- 再次执行相同 `run_id` 的命令，系统能准确从中断的步骤恢复并继续执行，且前面步骤的变量未丢失。

---

## 阶段三：工作流嵌套与元子工作流雏形 (V0.5)

**目标**：打通动态生成和调用子工作流的能力，让 Agent 能够“用工作流生成工作流”。

**核心任务**：
1. **变量作用域与嵌套执行**：
   - 解决变量命名空间污染问题（约定 `StepX.output` 规范或引入局部隔离）。
   - 让 `runner.py` 支持 `[SUB_WORKFLOW]` 标签，实现任务递归流转。
2. **注册表管理 (`registry_manager.py`)**：
   - 实现 `index.json` 的读写与版本控制逻辑。
3. **实现核心 META 工作流**：
   - 编写 `workflow_designer.step.md`：根据 Prompt 输出新工作流的 Markdown。
   - 编写 `registry_manager.step.md`：自动落盘并注册。
   - *(暂缓介入 `security_validator` 和自动化测试 `unit_test_generator`)*。

**里程碑 (Milestone 3)**：
- 向系统下发指令：“帮我创建一个代码 Review 工作流”。
- 系统能通过调用 META 工作流，自动在 `workflows/dev/` 下生成一个合法的 `.step.md`，并在 `index.json` 中完成注册。

---

## 阶段四：安全加固、上下文压缩与复杂工程化 (V1.0 - V2.0 终态)

**目标**：对标设计文档完整终态，补齐所有企业级高阶特性和安全门禁。

**核心任务**：
1. **上下文管理 (`context_manager.py`)**：
   - 实现 LLM Context 自动压缩，提取长步骤的历史摘要。
2. **自动化安全审计 (`security_validator.step.md`)**：
   - 引入 `bandit` 扫描。
   - 实现自动为生成的代码打上 `[DANGER]` 操作标识及死循环检测。
3. **自动化测试防护**：
   - 引入 `unit_test_generator`，确保 AI 生成的工作流通过 pytest 面试。
4. **全面补齐 Rollback 与高阶交互**：
   - 补齐如 `file_writer` 的 `.bak` 备份与还原机制。
   - 重构 `user_confirm`，接入 VS Code Extension 的 IPC 事件通知，实现弹窗化审批。
   - 引入真正的内存加扰与加密保险箱 (`secrets_vault.py`)。

**里程碑 (Milestone 4)**：
- 向系统下发一句需求即可闭环获得：设计审查 -> 源码生成 -> 依赖测试 -> 静态扫描 -> 沙箱试运行 -> 报告输出 的全自动工业级体验。
