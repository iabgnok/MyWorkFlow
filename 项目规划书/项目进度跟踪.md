### Phase 1：夯实 V1 基础底座（进行中）
*以重写当前 MVP 引擎使其达到工程可用级并引入异步、持久化机制为目标。*

#### 1.1 状态持久化与断点续传 (State Persistence)
- **目标**: 实现 `state_store.py` (基于 SQLite)，支持进程中断后按 `run_id` 恢复执行。
- **状态**: ✅ 已完成 (2026年4月1日)
- **测试结果**: *验证通过*。引入了 `aiosqlite` 以适配协程化，能够在中途强杀进程（如 step 2 崩溃）后，再次带入相同 run_id 从 step 2 继续，跳过 step 1 并完美还原 `context` 字典中的中间生成变量。

#### 1.2 异步运行改造系统 (Async Orchestration)
- **目标**: 改造 `runner.py` 为 `asyncio` 事件循环架构。
- **状态**: ✅ 已完成 (2026年4月1日)
- **测试结果**: *验证通过*。成功使用 `asyncio` 改造了入口逻辑，并在执行 Skill 时进行了适配（原生协程或通过 `asyncio.to_thread` 执行同步逻辑）。兼容并解决了 I/O 阻塞问题。

#### 1.3 错误策略引擎与定级 (Error Policy)
- **目标**: 实现 L0, L1, L2 类异常重试拦截策略。
- **状态**: ✅ 已完成 (2026年4月1日)
- **测试结果**: *验证通过*。新建了 `error_policy.py` 作为重试网关，包装在 `runner.py` 的技能调用周围。并在后续重构中引入了成熟的第三方库 `tenacity` 接管了手写 while 循环，支持了更精准的 AsyncRetrying 指数退避，代码更具有鲁棒性。

#### 1.4 引擎边缘用例外围加固 (Type-Safety & Secret Masking)
- **目标**: 解决 V1 MVP 遗留下来的类型破坏问题与敏感凭证落库风险。
- **状态**: ✅ 已完成 (2026年4月1日)
- **测试结果**: *验证通过*。
  1. 重构了 `parser.py` 中的 `replace_variables` 方法，引入了基于 `json.dumps` 的深度类型探测，解决了字典变量模板格式化后生成的 JSON 被单引号破坏的问题。
  2. 为 `state_store.py` 添加了 `_mask_secrets` 启发式脱敏拦截器，确保存入 SQLite 的 `context` 快照在落盘前会自动将含有 `api_key`、`password` 等敏感键名的变量值替换为 `******`。
  3. 新增了终端集成的综合测试脚本 `test_edge_cases.py`，三个隐患模块的修复用例均顺利 Pass。

### Phase 2：渐进式引入 V2 Agent 双回路评估模型（进行中）
*在有稳固引擎后开始攻克最大风险点“验证与质量闭环”，暂不引入高复杂度的 Planner。*

#### 2.1 上下文切断器 (Context Reset Framework)
- **目标**: 实装文档中提及的在多次修改反馈间实现上下文清理与 Artifact (中间交付物) 显式传递，防止幻觉。
- **状态**: ✅ 已完成 (2026年4月1日)
- **测试结果**: *验证通过*。引擎采用静态变量依赖 (`self.context`) ，不强制维持对话历史 `msg_history`，并在触发从 Evaluator 跳回 (Jump Back) 时，只传递 `Workflow_Draft`、错误反馈与 Escalation 次数作为系统干净的启动点。

#### 2.2 部署独立 Evaluator (质量与逻辑守门人)
- **目标**: 接入静态 Regex 与动态基于 LLM 的四维指标打分的审查角色。
- **状态**: ✅ 已完成 (2026年4月1日)
- **测试结果**: *验证通过*。开发了 `llm_evaluator_call.py` 节点。支持配置 `static_regex_scan` （优先通过正则扫描 `rm -rf` 等安全盲区），而后请求 LLM 执行 4 维打分，最终输出包含修复坐标 `defects` 的标准化 JSON 报告，并能产生 `__jump_to__` 动态影响 `runner.py` 流转。

#### 2.3 阶梯式升级反馈环 (Escalation Ladder)
- **目标**: 实现 1-4 轮自修复重试，第 4 轮严格阻断并呼叫人工。
- **状态**: ✅ 已完成 (2026年4月1日)
- **测试结果**: *验证通过*。改造了 `runner.py` 基于步骤数组的 `for` 循环为受控 `while` 游标状态流。引入 `jump_back_counters` 记录单步的被打回次数。成功测试了失败 3 轮后的标准放宽逻辑，以及失败 4 次时准确抛出 `[Escalation Ladder L4]` 异常拦截并呼叫人工。

*(后续 Phase 3 将随各阶段完成情况逐步解锁和详细记录测试)*
